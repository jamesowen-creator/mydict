## 3. 개념 지도 구현 결정
- 관계 5종: 사용·일부·종류·일으킴·구별. 연결 문구 1~40자 필수, 역방향 중복 거부, '구별'은 방향 무시로 정규화. 275-1부터 lib/cmap_map.js의 자체 상수(RELATION_TYPES)이며 개념학습 파일을 불러오지 않는다.
- 설명 항목: 정의 → 예시 → 쉬운 설명 → 더 깊게 설명(개념학습 방식 복사. 서버 한도 300/200/250/250, 정의 필수). 옛 4항목(정의/이 주제에서의 의미/쉬운 예/헷갈리기 쉬운 점)은 호환 표시. 주제 경로 맥락 입력, 지시문 삽입 방어, 한도 CMAP_EXPLAIN_DAILY_CAP 60/일, 모델 Haiku 유지. "AI 설명 · 확인 필요" 표시 유지.
- 해설(273-4 확정): 이야기체, 지도의 모든 개념 반영(서버가 id·용어 등장 검사, 내부 재시도 1회), 마지막에 개념 추가 제안(최대 3개, 자동 추가 없음). 저장된 지도에서만 생성(409 needs_save), 지도 해시가 바뀌면 stale 안내. 한도 CMAP_NARRATE_DAILY_CAP 10/일.
- 배치 최적화: AI 없이 계산, 미리보기·적용·되돌리기, 교차 수 비증가, 의미 해시(노드+간선, 좌표 제외) 서버 검증.
- 연결 퀴즈: start는 노드만 반환, 채점은 서버가 저장된 지도 기준(연결·유형·방향 따로, 추가 연결은 표시만 하고 감점 없음).
- 운영 DB 변경은 앱 시작 시 자동 생성(step 방식)만 사용.

## 4. UI 규칙 (274~275)
- 화면 전체가 한 번에 스크롤. 내부 스크롤 예외는 <dialog>와 지도 SVG 캔버스뿐. 섹션 박스 없음(라벨·간격·1px 선).
- 지도는 전체 화면 시트(<dialog id="map-sheet">, ≥768px에서는 큰 팝업): 닫기 버튼·ESC·뒤로가기, 자동 맞춤, 확대·축소, 툴바(개념 선택, 저장, 배치 최적화, 되돌리기, 전체 보기).
- 설명은 어디서나 읽기 형태(항목 이름+본문, 예시 인용선). 입력칸은 [수정]을 눌렀을 때만 나타나며 자동 높이(스크롤·크기 조절 손잡이 없음). 새 검색 결과 카드도 같은 렌더러를 공유하고 버튼은 [닫기][다시 설명][수정][저장]. 수정 중은 [취소][완료]([완료]는 카드에만 반영, 서버 저장은 [저장]).
- 이 구조는 사용자가 "박스를 만들지 말라"고 지적한 뒤 275-3에서 맞췄다(275-2는 입력칸 높이만 처리해 요구와 어긋났음).

## 6. 복습: 클릭 설명·모르는 개념 표시·표시 개념 퀴즈 (275-4, 275-5)
- 읽기 전용 지도 시트에서 개념 클릭 상태 전이(순수 함수 public/js/cmap/markState.js):
  · 표시 없음+팝업 없음 → 클릭: 간략 설명 팝업 + 표시 · 표시됨+팝업 열림 → 같은 개념 재클릭 또는 밖 클릭: 팝업만 닫힘 · 표시됨+팝업 없음 → 클릭: 표시 해제. 팝업이 열린 채 다른 개념을 누르면 앞 팝업을 닫고 새 개념에 규칙 적용.
- 편집 시트와 퀴즈 모드에서는 동작하지 않음. 드래그·핀치는 클릭으로 처리하지 않음(6px 기준) [핀치는 실제 폰에서 미확인].
- 팝업 내용: 개념 이름 + 정의 한 줄(서버가 지도 응답에 넣는 brief, 140자). 서버 요청·AI 호출 없음.
- 표시 표식: 면 색 surface-2 + 위험 잉크 3px 테두리 + 물음표 배지(색만으로 구분하지 않음). 해설 강조(코랄 테두리)와 구분됨.
- 저장: 사용자별·개념 단위 cmap_concept_marks(user_id, concept_id, marked_at). PUT /api/cmap/concepts/:id/mark(멱등), 지도 응답에 marked_concept_ids(주제 트리 기준). 표시는 지도 의미 해시에 영향 없음.
- 표시 개념 퀴즈(복습 탭 [표시한 개념 퀴즈] 버튼 하나, mode='marked'): 출제 연결 = 한쪽이라도 표시 개념인 연결, 제시 노드 = 연결 있는 표시 개념 + 이웃. 범위는 서버가 계산(클라이언트 값 무시), 연결 없는 표시 개념은 사전 안내, 출제 연결 2개 미만이면 시작 불가+[전체 퀴즈로 풀기]. 결과에 "모두 맞힌 표시 개념"과 [표시 해제](사용자가 직접, 자동 해제 없음). 보조 장치: GET /api/cmap/maps/:id/quiz/marked-info(개수·안내를 지도 기준 서버 계산), scope_key(시작 뒤 표시가 바뀌면 채점 거부 409 scope_changed).
- 알려진 한계: 퀴즈 기록(cmap_quiz_attempts)만으로는 전체 퀴즈와 표시 퀴즈를 구분할 수 없음(구분하려면 열 추가 필요, 별도 승인 작업).

## 7. OCR 터치 선택 (272)
- Tesseract.js 5.1.1. Worker 종료 경쟁 해결(새 워커는 이전 종료를 기다림, 취소 토큰, 정지 후 결과 무시).
- [자동 | 터치] 토글. 터치 모드는 자동 스캔을 멈추고 칩·안내를 숨김. 보이는 영역 스냅샷으로 인식하고 단어 상자를 투영. 터치 규칙: 8px 여유, 28px 이내 가장 가까운 단어. 필터: 알파벳, 2글자 이상, 신뢰도 30 이상, 단어 목록·불용어 필터 없음. 인식 제한 20초.
- 선택 목록(최대 20개, 중복은 "이미 담김", 위·아래·삭제, [검색 시작]→첫 단어부터 [다음]), 재진입 시 목록 유지.
- 검색 요청 번호(_searchSeq): 마지막 요청만 화면에 그림, 옛 요청도 단어장에는 저장, 같은 단어 동시 저장 방지. 미리 불러오기 없음. OCR 패널은 밝은 배경(칩만 예외).
- 폰 확인 보류: 칩 재선택, 모드 전환, 인식 시간·상자 정렬, 목록 편집·20개 제한, [검색 시작]/[다음] 연타, 목록 유지.

## 8. 작업·테스트 규칙 (사용자 결정 2026-10-13~14)
- 새 지시 블록은 **결과 보고가 와서 검토된 뒤에만** 만든다. 한 번에 하나씩. 보충 블록을 여러 개 겹치지 않는다("자꾸 꼬여").
- 변형 확인(뮤테이션 검사)은 블록에서 명시한 경우에만 한다.
- 테스트: 관련 묶음만(CSS만 변경=관련 화면+design_lint, 한 화면=그 화면+관련, 새 기능=신규+영향 기존+design_lint, 공용 헬퍼·권한·서버 공통 변경=전체 또는 멈추고 보고). 전체 테스트는 배치 끝에만. 부하성 UI 실패는 해당 파일만 최대 2회 재실행 후 통과하면 부하성으로 보고. 새 테스트는 t.after로 서버·페이지를 닫는다.
- 품질 판단은 나중에 한꺼번에(사용자가 폰에서 마지막에). 코딩 먼저.
- 모든 UI 작업은 디자인 원칙을 지킨다(아래). 커밋 메시지 끝에 Co-Authored-By와 Claude-Session 두 줄.
- 서비스워커: 같은 이름의 .js/.css가 바뀌거나 새 .js/.css가 추가되면 CACHE_NAME을 올린다(현재 v31). 앱을 완전히 닫았다가 다시 열어야 새 버전이 적용됨.

## 10. 향후 과제 (합의, 미착수)
- 복습 고도화 2단계: 주관식 질문(개념 자체를 묻고), 음성 답변, AI 평가·부족한 점 피드백. 사용자 합의(2026-10-14). AI 호출 비용이 생기므로 Haiku 먼저 제안. 결과를 나중에 어떻게 다시 상기시킬지(리마인딩)는 더 고민 필요. 1단계의 "모르는 개념 표시"가 기반이 될 수 있음.
- 개념 지도 vs 개념학습 비교 후 하나 삭제 결정. 삭제 시 정리 목록은 concept-map-redesign.md의 268-1 조사 B-5와 274-3 보고 참조. 운영 DB 테이블·열 삭제는 백업과 항목별 승인 필요.
- 274-2가 제안한 단순화 4가지(선택 목록 그룹·접기, 지도 힌트와 저장 상태 합치기, 해설 탭의 고정 지도 미리보기, 수정·삭제를 행 메뉴로): 사용자 선택 시에만.
- 긴 화면 개선 후보(접기/펼치기, 개수 제한): 주제 화면 개념 목록, 해설·복습·퀴즈 결과 목록.
- 수정 대화상자는 입력칸이 자라면 대화상자 안에서 스크롤됨([저장]이 밀림). 불편하면 전체 화면 페이지로 전환 검토.
- 퀴즈 기록에 전체/표시 구분이 필요해지면 열 추가(별도 승인).
- db_init.test.js 등의 절대 시간 단언(<500ms 등)은 부하에서 흔들릴 수 있음 [추정]. 서버 wordbook 갱신 API(2차 데이터 영구 저장), 이모지→SVG·999px 알약·간격 정리는 기존 열린 항목.
