## 3. 개념 지도 구현 결정
- [286-1에서 10종·문구 선택으로 변경, 12절·ui-280 10절 참고] 당시 기록: 관계 5종: 사용·일부·종류·일으킴·구별. 연결 문구 1~40자 필수, 역방향 중복 거부, '구별'은 방향 무시로 정규화. 275-1부터 lib/cmap_map.js의 자체 상수(RELATION_TYPES)이며 개념학습 파일을 불러오지 않는다.
- 설명 항목: 정의 → 예시 → 쉬운 설명 → 더 깊게 설명(개념학습 방식 복사. 서버 한도 300/200/250/250, 정의 필수). 옛 4항목(정의/이 주제에서의 의미/쉬운 예/헷갈리기 쉬운 점)은 호환 표시. 주제 경로 맥락 입력, 지시문 삽입 방어, 한도 CMAP_EXPLAIN_DAILY_CAP 60/일, 모델 Haiku 유지. "AI 설명 · 확인 필요" 표시 유지.
- 해설(273-4 확정): 이야기체, 지도의 모든 개념 반영(서버가 id·용어 등장 검사, 내부 재시도 1회), 마지막에 개념 추가 제안(최대 3개, 자동 추가 없음). 저장된 지도에서만 생성(409 needs_save), 지도 해시가 바뀌면 stale 안내. 한도 CMAP_NARRATE_DAILY_CAP 10/일.
- 배치 최적화: AI 없이 계산, 미리보기·적용·되돌리기, 교차 수 비증가, 의미 해시(노드+간선, 좌표 제외) 서버 검증.
- 연결 퀴즈: start는 노드만 반환, 채점은 서버가 저장된 지도 기준(연결·유형·방향 따로, 추가 연결은 표시만 하고 감점 없음).
- 운영 DB 변경은 앱 시작 시 자동 생성(step 방식)만 사용.

## 6. 복습: 클릭 설명·모르는 개념 표시·표시 개념 퀴즈 (275-4, 275-5)
- 읽기 전용 지도 시트에서 개념 클릭 상태 전이(순수 함수 public/js/cmap/markState.js):
  · 표시 없음+팝업 없음 → 클릭: 간략 설명 팝업 + 표시 · 표시됨+팝업 열림 → 같은 개념 재클릭 또는 밖 클릭: 팝업만 닫힘 · 표시됨+팝업 없음 → 클릭: 표시 해제. 팝업이 열린 채 다른 개념을 누르면 앞 팝업을 닫고 새 개념에 규칙 적용.
- 편집 시트와 퀴즈 모드에서는 동작하지 않음. 드래그·핀치는 클릭으로 처리하지 않음(6px 기준) [핀치는 실제 폰에서 미확인].
- 팝업 내용: 개념 이름 + 정의 한 줄(서버가 지도 응답에 넣는 brief, 140자). 서버 요청·AI 호출 없음.
- 표시 표식: 면 색 surface-2 + 위험 잉크 3px 테두리 + 물음표 배지(색만으로 구분하지 않음). 해설 강조(코랄 테두리)와 구분됨.
- 저장: 사용자별·개념 단위 cmap_concept_marks(user_id, concept_id, marked_at). PUT /api/cmap/concepts/:id/mark(멱등), 지도 응답에 marked_concept_ids(주제 트리 기준). 표시는 지도 의미 해시에 영향 없음.
- 표시 개념 퀴즈(복습 탭 [표시한 개념 퀴즈] 버튼 하나, mode='marked'): 출제 연결 = 한쪽이라도 표시 개념인 연결, 제시 노드 = 연결 있는 표시 개념 + 이웃. 범위는 서버가 계산(클라이언트 값 무시), 연결 없는 표시 개념은 사전 안내, 출제 연결 2개 미만이면 시작 불가+[전체 퀴즈로 풀기]. 결과에 "모두 맞힌 표시 개념"과 [표시 해제](사용자가 직접, 자동 해제 없음). 보조 장치: GET /api/cmap/maps/:id/quiz/marked-info(개수·안내를 지도 기준 서버 계산), scope_key(시작 뒤 표시가 바뀌면 채점 거부 409 scope_changed).
- 알려진 한계: 퀴즈 기록(cmap_quiz_attempts)만으로는 전체 퀴즈와 표시 퀴즈를 구분할 수 없음(구분하려면 열 추가 필요, 별도 승인 작업).

## 6b. 말로 설명하기: 주관식·음성 답변·AI 평가 (277-1 조사, 278-1 구현)
- 조사(277-1) [확인함]: 개념학습에는 주관식·답변 평가 기능이 **없다**(4지선다만, 음성은 입력창을 말로 채우는 용도). 전사 코드는 개념학습 라우트 안 지역 함수라 import 불가 → 복사. 따라서 이 기능은 새로 만든 것이다.
- 사용자 결정(2026-10-14): 질문 문장 없이 **개념 이름만 제시**하고 음성으로 답하게 함. 녹음 원문(전사)은 화면·DB·로그 어디에도 남기지 않고, AI가 정리한 "내가 말한 내용(요약)"만 보여 주고 저장. 전사 확인 단계 없음(녹음 종료 → 바로 평가). 오디오 저장 안 함. 리마인딩은 "최근 부족 목록"만(목록에서 다시 출제하는 기능 없음). 한도 전사 20/일, 평가 30/일. 출제 대상은 표시한 개념 중 저장된 설명이 있는 개념.
- 흐름: 복습 탭 [말로 설명하기](옆에 "대상 N개", GET /api/cmap/maps/:id/answer-targets) → 개념 이름만 표시 → 마이크 녹음(60초 자동 종료) 또는 [직접 입력으로 답하기] → "평가 중…" → 결과(판정 아이콘+글자, 내가 말한 내용 요약, 잘 말한 점, 부족한 점, 보완 한 줄, "AI 평가 · 확인 필요") → [다시 말해 보기]/[다음 개념]/[마치기]. [표시 해제]는 판정 '충분'일 때만, 사용자가 직접(자동 해제 없음).
- API: POST /api/cmap/concepts/:id/answer/voice(오디오 6MB·60초, webm/mp4/mpeg/wav → 서버 전사 → 평가), POST .../answer/text(JSON, 1000자), GET /api/cmap/answers/recent. 저장된 설명이 없는 개념은 400 no_explanation. 전사가 비면 422(평가 호출 없음).
- 전사: lib/cmap_stt.js(개념학습 코드 복사, 모델 VOICE_STT_MODEL 기본 gpt-4o-mini-transcribe, language ko, 오디오는 메모리에서만 다루고 저장 안 함).
- 평가: lib/cmap_answer.js(Haiku 'claude-haiku-4-5-20251001', temperature 0.2, max_tokens 700). 입력은 JSON(개념 이름·저장된 설명·사용자의 답), 지시문 삽입 방어, 평가 기준은 저장된 설명과의 비교(외부 지식으로 감점하지 않음), 음성 인식 오류 가능성을 맥락으로 해석. 출력 verdict 충분/부분적/부족, summary ≤300, strengths ≤3개×80, gaps ≤3개×100, supplement ≤150. 검증 실패 시 502·저장 없음·내부 재시도 없음.
- 한도·비용: 이벤트 cmap_stt(오디오 초 × 분당 단가), cmap_answer(Haiku 토큰). 환경변수 CMAP_STT_DAILY_CAP 기본 20, CMAP_ANSWER_DAILY_CAP 기본 30(코드 기본값, Railway 설정 불필요), 초과 시 외부 호출 전 429. routes/admin.js calcCost 반영. 1회 약 $0.005 [추정, 실측 아님].
- 저장: cmap_answer_attempts(user_id, concept_id, verdict, summary, strengths, gaps, supplement, input_mode, created_at; 원문·전사·오디오 열 없음; CASCADE; 인덱스 user_id+created_at DESC).
- 최근 부족 목록: 복습 탭 #answer-entry 안, 개념별 **최신 시도**가 부분적·부족인 것만 최근 순 최대 20개, 읽기 형태, 재출제 버튼 없음. 이후 '충분'이면 목록에서 빠짐.
- 화면 파일: public/js/cmap/answerView.js, micRecorder.js(개념학습 녹음 코드 복사).
- 검증 [확인함]: 전체 974건 통과, "원문은 응답·DB·로그 어디에도 없다" 테스트 통과, 금지 파일 diff 0줄. [추정/미확인] 실제 OpenAI 전사와 Haiku 평가 호출은 가짜로만 시험했으므로 음성 인식 정확도·평가 품질·응답 시간은 폰에서 확인 필요.

## 8. 작업·테스트 규칙 (사용자 결정 2026-10-13~14)
