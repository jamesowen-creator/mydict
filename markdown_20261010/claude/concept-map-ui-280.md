## 2. 합의된 사용 흐름 (사용자, 2026-10-15)
1. 랜딩 = 개념 지도 첫 화면. 상단 [주제 추가], 아래 주제 목록(최신순).
2. [주제 추가]: 상위 주제 → 하위 주제(선택, [하위 주제 추가]로 반복, 나중에도 추가 가능, 5단계, 같은 부모 아래 같은 이름 금지) → [완료] → 가장 마지막(최하위) 주제 안으로 들어가 거기에 머문다.
3. 주제 안 화면: 경로 한 줄(예: 금융 › 단기자금), 하단 고정 개념 입력 바 + [검색], 검색 결과와 저장된 개념이 한 흐름.
4. 주제를 바꾸려면 뒤로 가기 또는 하단 [주제] 탭(랜딩)으로 간다.
5. 하단 내비: 주제 / 퀴즈 / 지도 만들기 / 오답노트. 랜딩과 주제 안 화면 모두에서 보임.
- 사용자 결정: [주제] 탭 = 랜딩(오케스트레이터가 권장한 "현재 주제의 개념 화면"이 아님). 검색 결과 항목은 B안(정의/예시 2개, 쓰임새는 정의에 녹임). 자동 저장 + 삭제 버튼(삭제는 확인 창). 키보드가 열려 있는 동안 내비 숨김. 오답노트는 틀만 만들고 운영 방식은 검토 후 추가 개발.

## 3. 내비 4탭 (280-1)
| 탭 | 내용 |
|---|---|
| 주제 | 랜딩(주제 목록)으로 이동 |
| 퀴즈 | 카드 3개: 연결 퀴즈 / 표시 개념 퀴즈 / 말로 설명하기 (기존 기능 연결, 로직 변경 없음) |
| 지도 만들기 | [만들기 / 해설] 두 구분. 만들기=지도 선택·배치·연결·저장·최적화, 해설=이야기체 해설 + [지도 열기](읽기 전용 지도, 개념 클릭 표시) |
| 오답노트 | 모르는 개념 표시 목록 + 말로 설명하기 최근 부족 목록 + [지도에서 보기]. 새 기능 없음 |

- 키보드: 입력칸 포커스 시 내비 숨김. visualViewport 120px 이상 축소 감지는 코드만 있고 실제 소프트 키보드는 미확인 [추정]. 280-2에서 입력 바 안의 포커스는 키보드 열림으로 취급하도록 고침(검색 버튼을 누르는 순간 포커스가 빠져 내비가 복귀하며 클릭이 유실되던 문제) [확인함].
- 이동: 주제 안 진입은 pushState, 탭 전환은 replaceState, [주제] 탭은 쌓인 기록만큼 되돌아가 랜딩. 녹음·평가 중 탭 전환 시 이탈 확인(녹음 중은 테스트로 확인). 퀴즈 진행 중 확인은 코드만 있음(퀴즈가 모달이라 실제로는 탭을 누를 수 없음).

## 4. 280-1에서 달라진 점
- 주제 트리가 최신순 평면 목록으로 바뀌어 접기/펼치기가 없어졌다(하위 주제는 "금융 › 단기자금" 경로 표기).
- 예전 "복습" 탭의 읽기 전용 해설 표시는 해설 탭으로 이동. 읽기 전용 지도는 해설 탭의 [지도 열기]와 오답노트의 [지도에서 보기]에서 연다.
- 주제 안 화면의 [지도 보기]는 제거(내비 [지도 만들기]가 대신). 지도 단위는 선택한 주제의 최상위 주제이고 화면에 "‘과학’ 주제 전체의 지도예요." 안내가 있다.
- 하위 주제를 추가하면 그 하위 주제 안으로 이동(예전과 동일).
- 테스트: 기존 cmap UI 11개 파일 수정, 신규 cmap_nav.ui.test.js(7개)와 helpers/cmap_nav.js. 접기/펼치기 검증은 삭제. cmap_marks의 시트 닫기 직후 클릭 flake에 200ms 대기를 넣음(근본 해결 아님) [확인함: 이후 전체 통과].

## 5. 280-2 내용
- 하단 입력 바: 내비 바로 위 고정, 입력창+[검색] 44px 이상, 본문 하단 여백은 내비+입력 바 높이를 측정해 반영, 포커스는 코랄 테두리+링.

- 카드: 이전 결과·저장된 개념은 "개념명 · 저장됨" 한 줄, 눌러서 펼침/접힘. 오래된 것이 위, 최신이 아래(입력 바 위). 버튼 [다시 설명][수정][삭제], 닫기 버튼 없음. 검색 중·오류·"이미 있는 개념" 안내는 목록 맨 아래 임시 카드.
- 수정: 카드 안 입력칸(이름·영문·메모·값이 있는 설명 항목), [취소][완료], [완료]가 서버 PATCH까지 반영. 개념 수정 대화상자는 [개념 추가](직접 입력)에만 남음.

- 말로 설명하기·해설은 값이 있는 설명 항목 전부를 비교 기준으로 써서 2항목·4항목 개념 모두 동작(서버 테스트로 모델 입력까지 확인).

## 7. 심화 개념 (282-1, 283-2)
- 카드 버튼 [심화 개념]을 누를 때마다 항목이 하나씩 쌓인다. 이름은 "심화 개념 1." ~ "심화 개념 3."(번호 뒤 마침표), 개념당 최대 3개, 항목당 350자 이하, 덮어쓰기 없음. 관점은 개수에 따라 1번째 작동 원리·구조, 2번째 실무 쟁점, 3번째 비슷한 개념과의 구별·한계·주의점. 버튼 옆에 "N/3", 3개면 비활성. [수정]에서 입력칸을 비우고 [완료]하면 그 항목 삭제. 카드 버튼 순서 [심화 개념] [다시 설명] [수정] [삭제].
- 저장: 설명 JSON의 새 키 deepen(문자열 배열)을 쓴다(DB 컬럼 추가 없음). 옛 deeper_text는 옛 이름으로 그대로 표시하고 3개 한도에 포함하지 않는다. [다시 설명]은 정의·예시만 다시 만들고 deepen은 보존한다. 심화 항목을 사람이 고치면 설명 전체의 출처가 manual로 바뀐다(기존 PATCH 규칙).
- 서버: POST /api/cmap/concepts/:id/deepen. Haiku(claude-haiku-4-5-20251001). 3개면 AI 호출 전 409, 같은 개념의 진행 중 중복 요청 409(서버 메모리 잠금이라 서버가 여러 대면 서버 간에는 막지 못함, 저장 직전 행 잠금과 개수 재확인이 마지막 방어선), 한도는 설명 생성 한도(CMAP_EXPLAIN_DAILY_CAP 60/일)와 합산(같은 이벤트 cmap_explain), 검증 실패는 502·저장 없음.
- 말로 설명하기·해설·간략 설명(brief)은 문자열 키만 읽어서 deepen이 자동으로 제외된다 [확인함].
- 283-2 안정화: 처음에 폰에서 [심화 개념+]를 눌러도 "설명을 가져오지 못했습니다"가 나왔다(일반 검색은 정상). 원인 후보는 모델 출력이 350자 한도를 넘음(프롬프트 안내 300자와 한도 350자의 간격이 17%뿐), JSON 형식 깨짐 [추정, 사용자 화면 문구만으로는 구분 불가]. 조치: 프롬프트 안내를 260자 안팎으로 낮춤(검증 350자 유지), 공용 JSON 파서가 코드 블록 제거 후 실패하면 첫 JSON 객체만 꺼내 한 번 더 파싱(검증은 약화하지 않음), 실패 로그를 reason=api_error/bad_json/too_long/empty/bad_shape와 글자 수로 구분(원문은 남기지 않음). 표기는 버튼 [심화 개념](+ 없음). 실제 Haiku에서 성공하는지는 폰 확인 전 [미확인].

## 8. 지도 만들기 첫 화면과 캐시 불일치 방지 (283-1 진단, 283-2)
- 사용자 보고: [지도 만들기] 탭에서 "만들기"를 눌러도 반응이 없었다. 원인 [확인함: 283-1 코드·재현]: [만들기 / 해설]은 지금 보는 화면을 가리키는 구분 탭일 뿐이라 눌러도 동작이 없었고, 지도는 [지도 열기] → 시트 안 [개념 선택]으로 만드는 구조였다(280-1 설계 문제).
- 283-2 개편: [만들기] 첫 화면에 안내("‘금융’ 주제 전체의 지도예요. 다른 최상위 주제의 개념은 이 지도에 나오지 않아요.") → 저장된 개념 체크 목록(주제 경로별 묶음) → "N개 선택" → 주 버튼. 지도가 비었으면 [이 개념으로 지도 만들기](2개 이상 선택해야 활성), 이미 지도가 있으면 상태 한 줄과 [지도 열기](체크를 바꾸면 [선택한 개념으로 지도 열기]). 개념이 0개면 안내와 [주제로 가기]. 연결 있는 노드를 내리면 기존 확인 창. 지도에 올리는 일은 시트 [개념 선택]과 같은 함수(pickNode, applySelection) 재사용.
- 캐시: 283-1 재현 [확인함] — 옛 지도 JS와 새 HTML이 섞이면 하단 내비 탭이 전부 죽는다(서비스 워커가 JS는 cache-first, HTML은 network-first, HTML의 JS ?v= 값이 계속 1이었음). 조치: HTML의 JS 주소 ?v= 값을 sw.js CACHE_NAME 버전과 같게 두고 함께 올린다(정합 테스트 concept_map_cache.test.js). 내비 클릭 핸들러의 모듈 호출을 try/catch(console.error)로 보호. 배포 때마다 sw 버전과 ?v= 값을 함께 올려야 한다.

## 9. 지도 저장 안내와 시트 툴바 (284-1 조사, 285-1)
- 사용자 보고: 해설을 만들려는데 "저장된 지도에서만 가능"이라고 하는데 저장 버튼이나 순서를 찾을 수 없음. 원인 [확인함: 284-1]: [저장]은 편집 시트(지도 만들기에서 연 시트)에만 있고, 해설·퀴즈·오답노트의 [지도 열기]로 연 시트는 읽기 전용이라 개념 선택·저장·배치 최적화가 숨겨진다. 해설 화면 문구는 "지도 탭에서 [저장]"이라고 했지만 그런 탭이 없었다.
- 285-1: 해설·연결 퀴즈·표시 개념 퀴즈에서 지도가 저장되지 않았으면 [지도 저장하고 해설 만들기] / [지도 저장하고 퀴즈 시작] / [지도 저장하고 표시 개념 퀴즈 시작](서버에 새 라우트 없이 화면에서 저장 → 이어서 호출, 저장 실패 시 이후 호출 없음, 저장 성공 뒤 실패하면 저장 유지). 옛 해설이 있고 지도가 바뀐 경우는 [지도 저장하고 다시 만들기]. 개념이 없으면 [지도 만들기로 가기]. 말로 설명하기는 지도 저장 요구가 없어 변경 없음.
- 만들기 화면에 지도 상태 줄("저장 안 됨 / 저장 후 변경됨 / 저장됨 · 개념 N개 · 연결 M개")과 [지도 저장]. 읽기 전용 시트 상단에 "읽기 전용이에요. 수정은 지도 만들기에서 할 수 있어요."와 [지도 만들기로 가기].
- 편집 시트 툴바: 윗줄 저장 상태 + [저장], 아랫줄 [개념 선택] [전체 보기] [더보기]. [더보기] 목록에 배치 최적화, 되돌리기(최적화 적용 직후에만), 확대, 축소. 이전 툴바는 390px에서 되돌리기까지 7개가 되면 "배치 최적화" 라벨이 넘치고 320px에서 겹칠 수 있었음. 저장 함수는 mapView.js save() 하나로 공용({ ok, error }).
- 지도를 만든 뒤 개념을 추가해도 지도를 고칠 수 없다는 보고(2026-10-16)는 284-1에서 재현되지 않았다. 가장 가능성 높은 원인은 위의 읽기 전용 시트 [추정].

## 10. 관계 유형 10개·방향 없음·문구 선택 (284-1 조사, 286-1, DB 36단계)
- 사용자 결정(2026-10-16): 연결이 두 개씩만 되는 점(1:n 필요), 항상 화살표 방향이라 수평 관계를 설명하기 어려운 점, 관계 유형이 더 필요한 점, 연결 문구를 매번 텍스트로 넣기 번거로운 점을 개선.
- 유형 10개(순서 고정): 방향 있음 6 — 사용, 일부, 종류, 일으킴, 선행(A 다음에 B, 순서·단계), 조건(A가 B의 전제·조건). 방향 없음 4 — 구별, 유사, 대립, 연관. 기존 5개 유형과 저장된 지도는 그대로 호환.
- 방향 없음 4개: 방향 선택 없음([방향 바꾸기] 비활성), 화살촉 없는 선, 저장은 작은 id를 from으로 정규화, reverse 거부, 퀴즈에서 방향 채점 제외(결과 ↔ 표시). 선 모양: 구별·유사·연관은 기본 선 색 실선, 대립은 위험 토큰 색(var(--color-danger)) 점선(색만으로 구분하지 않기 위해 점선 보조 단서 — 제안한 오케스트레이터 추가안).
- 연결 문구는 선택(1~40자, 비우면 NULL). 유형도 문구도 없으면 400. 서버가 모든 응답에 display_label = 문구 ?? 유형 이름을 채워 화면·퀴즈 결과·해설 입력이 같은 값을 쓴다. 의미 해시는 문구를 NULL 명시로 정규화하며 기존 문구가 있는 연결은 이전과 같은 값이라 저장된 지도의 저장 상태가 유지된다 [확인함: 테스트].
- 유지되는 제약: 같은 두 개념 사이에는 방향과 관계없이 연결이 하나만 가능 [확인함: 284-1].
- DB 36단계 cmap_edges_types_v2 (맨 끝에 추가, 총 36단계): pg_constraint에서 relation_type·label 컬럼 기준 CHECK를 찾아 DROP(제약 이름을 가정하지 않음) → label NOT NULL 해제 → 이름 붙인 새 CHECK 3개(유형은 10값 또는 NULL / 문구는 NULL 또는 공백 아닌 1~40자 / 유형·문구 중 하나는 필수). 한 트랜잭션, LOCK TABLE cmap_edges, 재조회로 멱등, 기존 행 수정·삭제 없음. 단계가 실패해도 서버 시작과 다른 기능에는 영향이 없고(단계 실패 격리) 새 유형과 빈 문구 저장만 DB가 거부한다 [확인함: 코드·테스트]. 새 유형·NULL 문구가 저장된 뒤에는 옛 CHECK를 다시 걸 수 없다(되돌리려면 그 행을 먼저 옮기거나 NOT VALID).
- 해설 입력은 display_label과 '방향 없음' 표시를 쓰고, 프롬프트가 새 유형 6개의 뜻을 설명한다. 연결 대화상자의 유형 select는 서버 목록(방향 있음/없음 묶음)으로 채운다.
- 실제 PostgreSQL에서만 확인되는 부분(DDL 실행, 제약 교체, 잠금)은 fake DB와 SQL 문자열 테스트로만 검증했다. 배포 후 Railway 로그 "[DB] cmap_edges: 관계 종류 10값, 문구 선택화"와 "[DB] init done: 총 36단계, 실패 0단계"로 확인해야 한다 [미확인].

## 11. 1:n 한 번에 연결 (287-1)
- 시트에서 노드 하나를 고른 동안 [여러 개에 한 번에 연결] 버튼이 나온다(편집 시트만, 읽기 전용·퀴즈·미리보기에는 없음). 기존 두 노드를 차례로 탭하는 흐름은 그대로.
- 대화상자: 시작 개념 고정, 지도의 다른 노드 체크 목록(이미 연결된 노드는 "이미 연결됨"으로 비활성), "N개 선택"과 [모두 선택](이미 연결됨 제외, 오케스트레이터가 요청하지 않은 추가 항목), 유형 select(연결 대화상자와 같은 서버 목록·안내), 문구(선택), 방향 안내 한 줄. [연결 N개 만들기]는 선택 0개 또는 유형도 문구도 없으면 비활성, 만드는 중 중복 클릭 방지.
- 서버: POST /api/cmap/maps/:id/edges/bulk { from, to_ids, relation_type, label? }. 한 트랜잭션, 지도 행 잠금, 단건 API와 같은 함수(readEdgeInput, insertEdge) 재사용(규칙 복제 없음). 모든 검증은 INSERT 전에 하고 오류(없는 노드, 자기 자신, 잘못된 유형, 대상 0개, 51개 이상)는 400으로 전체 거부. 이미 연결된 쌍(방향 무시)은 건너뛰고 skipped 응답. 대상 수 상한 50(중복 제거 후 기준). 응답 { edges(display_label 포함), skipped, status }, 새로 만든 것이 있으면 201, 모두 건너뛰면 200.
- 저장 모델은 선 n개 그대로(그룹 객체 없음)이므로 퀴즈·해설·배치·표시 범위에 변경이 없다.
