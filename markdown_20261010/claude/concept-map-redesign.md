# 개념 지도 전면 개편 (설계·진행)

> [작업 311] 개념학습 화면·API·DB 테이블은 CL-1(cfa63d1, 2026-10-19)에서 삭제되었다. 이 문서의 개념학습 서술은 삭제 전 기록이며 현재 코드와 다르다. 현황은 orchestrator-handover.md의 "개념학습 삭제" 절.

기준일: 2026-10-14. 상태: **구현 완료**(1~5b, UI 개편, 개념학습 분리, 모르는 개념 표시, 표시 개념 퀴즈). 폰 확인은 보류. 구현 결과·결정·향후 과제는 **claude/concept-map-progress-275.md가 최신**이고, 이 문서는 설계 배경과 결정 기록이다(아래 본문은 2026-10-13 시점 그대로이며, 단계 표의 "지시 전" 같은 표현은 낡았다). 이 문서는 concept-study-design.md(1차), concept-study-phase2.md(2차), map-quality-227.md(지도 품질)를 이어받아 방향을 바꾼다.

## 개발 방식 (사용자 결정, 2026-10-13)
- 기존 개념학습은 갈아엎지 않는다. 새 구조는 **별도 메뉴 "개념 지도"로 개발**한다.
- 완성되면 **두 메뉴를 비교해서 써 보고, 하나를 삭제할 예정**이다(사용자). [결과: 개념학습이 CL-1(2026-10-19)에서 삭제됨] 즉 "대체 확정"이 아니라 "비교 후 선택"이며, 새 메뉴가 선택되지 않을 수도 있다.
- 따라서 개발 중에는 옛 개념학습 화면·데이터·API가 그대로 동작해야 한다(옛 파일은 수정하지 않는다).
- 홈 메뉴에 "개념 지도" 항목을 추가한다(사용자가 두 메뉴를 나란히 쓰며 비교하기 위해). 단, 개발 중에는 권한(perm_concept_map, 기본 꺼짐)을 받은 계정에게만 보인다.
- 비교 후 선택에 필요한 것: 옛 개념학습의 데이터를 새 구조로 옮길 수 있는지(268-1 B-5 참고)와 어느 쪽을 지워도 다른 쪽이 영향받지 않는 분리. 삭제 시점의 정리 목록은 B-5에 있다.

## 확정된 결정
- 메뉴 이름 "개념 지도"(가칭 아님, 비교 후 이름 재검토 가능).
- 연결은 사용자가 직접 한다(AI 연결 제안 없음). 선택적 "AI 관계 제안"은 나중에 필요할 때.
- 하위 주제: 개수 제한 없음, 언제든 추가 가능. 자료 구조는 부모 참조(중첩 가능), **최대 깊이 5단계**, 화면은 처음 1단계. **같은 부모 아래 같은 이름 금지(대소문자 무시)**.
- 지도 개수: 구조는 최상위 주제당 여러 개를 허용(cmap_maps), 화면은 처음에 지도 1개로 단순하게. [사용자 "동의" 2026-10-13]
- 배치 최적화는 계산 알고리즘(AI 호출 없음). AI는 설명(4단계)과 해설(10단계)에만 사용하고 기본 모델은 Haiku.
- 연결 퀴즈는 새 메뉴의 복습 단계에만 넣는다.
- 관계 표현: 연결마다 짧은 관계 문구(≤40자)를 사용자가 입력하고, 관계 종류는 선택 사항(권장: 227에서 검증한 5종 틀 재사용, 3단계 직전 확인).
- 나중에 정할 것(해당 단계 직전에 확인): 하위 주제 삭제 정책(권장: 개념을 부모로 옮긴 뒤 삭제), 설명 변조 방지 봉인 토큰(권장: 처음엔 불필요), 퀴즈의 "지도에 없는 연결"(권장: 표시만, 감점 없음), 옛 AI 연결 이전 안 함, 한도(설명 60/일, 해설 10/일).

## 요건 메모 (사용자)
- 하위 주제는 계속 추가할 수 있어야 한다. 개념 저장 후나 지도 작성 후에도 언제든 가능.
- 퀴즈 유형 추가: "개념을 흩어 놓고 연결하는 문제". 정답은 사용자가 저장한 최종 지도의 연결. 채점은 AI 없이 계산(비용 0). 연결·종류·방향을 따로 부분 채점. 모바일 입력은 "노드 A 탭 → 노드 B 탭" 방식이고 지도 편집(7단계)과 같은 컴포넌트(pairPicker)를 공유하는 안.
- 지도 내용이 사실과 다를 수 있으므로 개념 설명의 "AI 설명 · 확인 필요" 표시 원칙은 유지.

## 개편 이유 (사용자 진술)
- 개념 지도를 만들어 실제로 적용해 봤더니 AI가 그리는 지도가 너무 복잡하고 의미가 거의 안 보인다.
- 그래서 AI가 지도를 만드는 방식에서, 사용자가 직접 개념을 고르고 배치·연결하는 방식으로 이용 흐름을 바꾼다.

## 최종 이용 흐름 (사용자 확정)
1. 사용자가 최상위 주제를 생성한다.
2. 필요한 만큼 하위 주제를 추가한다.
3. 현재 주제의 맥락에서 낯선 개념을 검색한다.
4. AI의 백과사전형 설명을 읽고 개념을 저장한다.
5. 저장된 개념을 간략한 목록에서 관리한다.
6. 사용자가 지도에 사용할 개념을 선택한다.
7. 개념을 배치하고 직접 관계를 연결한다.
8. AI가 의미를 변경하지 않고 지도 배치를 최적화한다.
9. 사용자가 최종 지도를 저장한다.
10. AI가 지도에 연결된 요약·흐름·기억용 해설을 생성한다.
11. 사용자는 해설과 지도를 함께 보며 학습하고 복습한다(복습에 연결 퀴즈 포함).

(이전 흐름은 과제명·소주제 입력 → 개념 검색 → AI 백과사전식 설명 → 지도 만들기 → AI가 지도 위에 개념 나열 → 사용자 연결 → AI 설명 → 기억 보조였고, 위 11단계로 대체됨.)

## 현재 구현과의 차이
| 항목 | 현재(개념학습) | 개편(개념 지도) |
|---|---|---|
| 시작점 | 개념 하나 또는 질문 | 최상위 주제 |
| 하위 구조 | group_label(문자열) | 하위 주제(독립 항목, 부모 참조) |
| 개념 추가 | 입력하면 설명·제안·연결이 한 번에 생성 | 맥락에서 검색, 설명을 읽고 저장 |
| 다음 제안 | 있음 | 없음 |
| 연결 | AI 자동(b2/b3) + 사용자 수정 | 사용자 직접 |
| 배치 | 자동 레이아웃 | 사용자 배치 + 의미 불변 최적화 |
| 지도 저장 | 없음(즉석 계산) | 저장본 |
| 해설 | 없음 | AI 요약·흐름·기억용 |
| 복습 | 돌아보기 퀴즈 | 해설+지도 복습 + 연결 퀴즈 |

## 원칙
- 지도의 의미(개념·관계)는 사용자만 정한다. AI는 설명과 해설, 배치 계산만 맡고 관계를 만들거나 지우지 않는다.
- 배치 최적화 전후로 개념 수·연결 수·관계 종류·방향이 동일해야 하며 서버가 이를 검증한다.
- AI 설명은 기존 사실성 원칙을 유지한다(AI 설명·확인 필요 표시, 불확실하면 비움).
- API 비용이 드는 작업은 Haiku를 먼저 쓰고, 품질이 부족할 때만 Opus를 사용자에게 묻는다.
- 개발 중에는 옛 개념학습의 테이블·API·화면·공용 파일(mapCore.js 포함)을 변경하지 않는다.
- 새 화면은 디자인 원칙을 지킨다(design_lint 기준선을 늘리지 않음).
