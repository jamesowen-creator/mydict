# METIS 미니멀 디자인 원칙

이 문서는 METIS 하위 앱 화면을 디자인할 때 따르는 공통 원칙이다.
새 화면을 디자인할 때 이 문서를 프롬프트에 첨부하거나 참고하면
일관된 톤을 유지할 수 있다.

## 톤 & 철학
- 미니멀, 콘텐츠 중심 — 장식적 요소와 화려한 색 최소화
- 정보 계층은 색상보다 굵기/크기/여백으로 표현
- "이게 꼭 필요한가?"를 먼저 묻고, 없어도 되는 요소는 뺀다

## 색상
- 배경: 흰색 또는 아주 옅은 회색(#F7F7F8 근처)
- 텍스트: 진한 회색 계열(#1A1A1E), 보조 텍스트는 중간 회색(#6B7280)
- 포인트 컬러는 화면 전체에 최대 1개(짙은 슬레이트 톤 등), 남용 금지
- 라이트/다크 모드 토큰을 항상 쌍으로 정의 (다크: 배경 #151619 근처,
  텍스트 #F1F1F2 근처)

## 타이포그래피
- Noto Sans KR(또는 프로젝트 지정 폰트) 하나로 통일
- 계층은 폰트 크기+굵기 조합으로: 표제/제목은 크고 굵게(700~800),
  본문은 보통 굵기, 보조 정보는 작고 연하게
- 섹션 라벨은 작은 대문자 스타일(12px, weight 700, letter-spacing,
  uppercase, 보조색)로 통일

## 레이아웃/컴포넌트 규칙
- 카드 박스, 둥근 뱃지·필 UI 사용 금지 — 구분은 여백과 1px 구분선으로
- border-radius는 검색창과 주요 액션 버튼에만 적용(10~14px), 나머지는
  각지게
- 선택/활성 상태는 색상 단독이 아니라 굵기+밑줄(또는 굵기+아이콘
  변화) 등 최소 2가지 신호로 표현
- 예문/인용처럼 강조가 필요한 텍스트는 왼쪽 세로선(accent 컬러
  2px)으로 표시
- 아이콘은 인라인 stroke SVG만 사용, 이모지(국기 포함) 사용 금지
- 카운트 표시(뱃지 숫자 등)는 빨간 원형 뱃지 대신 라벨 옆 작은
  보조색 숫자로

## 사용성
- 버튼/터치 영역 44px 이상
- 실제 `<button>`/`<a href>`/`<input>`+`<label>` 사용, div에 onClick만
  붙이지 않기
- 작은 화면에서도 잘리거나 겹치지 않게 반응형 고려
- 라이트/다크 모드 둘 다 대비 확인
